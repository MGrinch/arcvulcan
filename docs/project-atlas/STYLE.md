# How to read these project pictures

Start with the purpose at the top. Follow the labeled arrows from an idea, request, answer or other starting information to a useful result. Return paths explain what the project remembers or improves before the next pass.

| Symbol | Meaning | Color |
| --- | --- | --- |
| Person | Someone supplies an idea, answer or decision | Slate blue |
| Slanted input shape | Information coming into the work | Gray |
| Rounded shape | Work being done | Blue |
| Diamond | A question or choice | Amber |
| Cylinder | Knowledge or history kept for later | Purple |
| Document shape | A useful result | Green |

Arrows have their own meaning: **blue** carries information or work; **amber** marks a choice or check; **purple** remembers or improves something; **green** delivers a useful result. Words on each arrow explain the actual relationship; color is never the only clue.

The status beside the title distinguishes existing code, written procedures, designs, archived prototypes, and early ideas. Existing code does not mean a service is running or that a learning benefit has been demonstrated. A picture explains a representative product workflow, not every internal function call.

SVG keeps text and lines sharp at any zoom. The editable Mermaid source uses Mermaid 11.12.0 with HTML labels disabled and the Lucide UserRound icon registered locally; the SVG needs no icon service, script, or internet connection. Model JSON preserves the node, relationship and evidence data. Icon license notices are embedded in each SVG and repeated in THIRD-PARTY-NOTICES.txt.

The approach draws on [C4's guidance for readable notation](https://c4model.com/diagrams/notation), [Mermaid's established shapes](https://mermaid.js.org/syntax/flowchart.html), [Diagrams' labeled and colored connections](https://diagrams.mingrammer.com/docs/guides/edge), [Lucide's consistent symbols](https://github.com/lucide-icons/lucide), and [W3C's guidance against color-only meaning](https://www.w3.org/WAI/WCAG22/Understanding/use-of-color.html). These are product explanations, not a claim of formal C4 conformance.
